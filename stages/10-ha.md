# Stage 10: Juju controller HA with a shared PostgreSQL primary

Branch `pg-poc/10-ha`, to be created on `pg-poc/09-bootstrap`.
Status: not started; follows functional single-controller comparison.
Read D9, D19, D22, D39 and D41, plus Stage 8's approved join contract.

## Scope

Three Juju controllers connect to one writable PostgreSQL primary. This
is Juju `enable-ha`, not a PostgreSQL replication/failover experiment.
No read-replica routing, multi-primary database or database-primary failure
is required. Losing the only PostgreSQL primary is not the fault under test.

## Tasks

**10-join:** verify config propagation (`db-backend`, `db-url`, `db-ca-cert`)
through controller config and instancecfg into new agents. Existing schemas
must open without fresh-bootstrap initialisation. Confirm controller-node
records and enumerate the dqlite-only hooks that are bypassed. Check total
connection usage across controllers/models against the server budget.
Then run `enable-ha -n 3` on the explicitly targeted disposable controller.

**10-healthy:** establish evidence that all controllers are operational,
leases coordinate mutually exclusive work, each controller receives
relevant change-stream events, and witness/pruning progress is safe.
Observe watcher readiness before test mutations, including valid empty
initial events; do not infer readiness from constructor return.

**10-failure-rejoin:** choose a specific Juju controller node and fault
mechanism; identify its API-serving/lease-owning roles rather than assuming
an "API leader". Stop that node, perform a real mutation, observe safe
lease takeover and convergence, then restart/rejoin it and verify stream
recovery and continued operation. Never stop the PostgreSQL hosting node.

## Contract to settle before execution

Specify observable lease safety, takeover/time bounds, per-controller
event evidence and witness retention/pruning expectations for stopped and
restarted consumers. Select targeted tests and a repeatable fault/recovery
procedure with bounded waits and cleanup. These are acceptance questions,
not instructions to add a new HA design.

Acceptance requires healthy concurrency and controller loss/rejoin evidence,
not just successful `enable-ha` or `status`. Follow race/stress requirements
for any changed concurrency code. Route shared runtime fixes back to their
owning stages. A later PG-primary failover test would require a separate
scope decision and endpoint/reconnection contract.
