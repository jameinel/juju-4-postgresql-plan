# Juju 4 on PostgreSQL: dqlite coupling analysis

Status: historical exploration for [PLAN.md](PLAN.md), captured against
`a8591fe1b8` (Juju 4.1 development). Not current implementation guidance.
Read only the section a task needs. Current DECISIONS.md and stage files
supersede proposals here; counts, paths and line numbers need rechecking.
Later schema observations are in [history](history/schema-generation.md).

## Summary

Juju 4 is coupled to dqlite at four levels:

1. **Node/cluster runtime**: embedded dqlite node lifecycle, HA clustering,
   bootstrap. Replaceable behind existing interfaces.
2. **SQL dialect**: schema DDL, ~307 triggers, a handful of query functions,
   raw `?` placeholders, sqlair's `@sqlair_N` placeholders.
3. **Driver semantics**: error classification and retry rely on SQLite error
   codes; domain code assumes dqlite's single-writer serialisable behaviour.
4. **Change stream**: correctness depends on change_log IDs becoming visible
   in commit order, which PostgreSQL sequences do not guarantee.

Not coupled: backups (logical YAML exports via domain services), the vast
majority of domain sqlair queries, apiserver facades (dqlite mentions are
comments).

## 2. Namespaces

- One logical database per namespace: `controller` plus one per model UUID.
- No cross-database queries or `ATTACH`; documented in
  `domain/schema/doc.go`.
- Model DBs are created lazily on first `GetDB` (`ensureModelDBInitialised`)
  and deleted by the undertaker via `DBDeleter.DeleteDB`.
- `namespace_list` / `model_namespace` tables in the controller DB track
  known namespaces.

## 3. sqlair

- Inputs are emitted as `@sqlair_N` with `sql.Named(...)`
  (`sqlair/internal/expr/querybuilder.go`); outputs aliased `AS _sqlair_N`.
- PostgreSQL drivers do not accept `@name` through `database/sql` (and `@` is
  a PG prefix operator). Requires rewriting to `$N`: in-tree driver wrapper
  (PoC) or an upstream sqlair dialect option (long term).
- Insert expressions may reuse the same named input more than once; the
  rewriter must map each name to a single positional parameter.
- sqlair's parser targets SQLite syntax; PG-only syntax (`::type`, dollar
  quoting, `@>`) should be avoided in shared queries.

## 4. Schema / DDL (`domain/schema`)

- 69 numbered patch files (31 controller, 38 model). Roughly 344 tables,
  79 views, 281 indexes, ~406 `REFERENCES` clauses.
- ~307 `CREATE TRIGGER` definitions: 234 generated by `generate/triggergen`
  into `*/triggers/*.gen.go`; the rest built in Go (`triggers.go`,
  `modeltriggers.go`). `triggergen` introspects a temporary dqlite DB.
- Patch engine `core/database/schema`: patches are chained SHA-256 hashes of
  the SQL text; bookkeeping table `schema` uses `INTEGER PRIMARY KEY
  AUTOINCREMENT` and `strftime("%s")` (query.go). Applied in one `StdTxn`.
- Release snapshots `*/4.0.15-*-release.ddl` are not loaded at runtime.
- Seed/reference data with fixed integer IDs (life, edit types, namespace IDs
  >= 10000 for custom triggers, etc.) must be preserved verbatim.
- Declaration order: SQLite resolves `REFERENCES` targets and view sources
  only when they are used; PostgreSQL resolves them at `CREATE` time.
  Captured 2026-10-23 as (referrer, target) pairs whose target is created
  later:
  - Controller: 7 (4 FK, 3 view; 2 within one patch).
  - Model: 70 (34 FK, 36 view; 11 within one patch).
  - Model patches 0004, 0005, 0010, 0011, 0014, 0015, 0018-0021, 0024 and
    0027 form one dependency cycle, as do 0008/0009 and 0032/0034, so
    renumbering patches cannot fix the order. Statements would have to move
    between patches.
  - There are no table-level FK cycles and no dangling references.
  - PostgreSQL also needs an FK's target columns to be a primary key, a
    unique constraint or a non-partial unique index when the FK is
    created. Four FKs rely on a unique index: `permission_object_access`
    (controller), and `space(name)`, `machine(name)` and
    `resource(uuid, charm_resource_name)` (model).

| SQLite construct | Count | PG translation |
|---|---:|---|
| `INTEGER PRIMARY KEY AUTOINCREMENT` | 4 | `bigint GENERATED BY DEFAULT AS IDENTITY` |
| `DATETIME` / `TIMESTAMP` types | 38 / 26 | `timestamptz` (decide precision/tz policy) |
| `strftime(...)` defaults | 7 | `now()` / `clock_timestamp()` |
| `BOOLEAN` | 46 | `boolean` (check seed values / comparisons) |
| `BLOB` / `REAL` | 6 / 6 | `bytea` / `double precision` (see `domain/schema/storage.go` text-vs-bytes notes) |
| `IIF` | 3 | `CASE` |
| Generated columns | 3 | `GENERATED ALWAYS AS (...) STORED` |
| `STRICT` | 1 | drop |
| Trigger bodies (`BEGIN...END`, `RAISE(FAIL, ...)`, `WHEN`, `UPDATE OF`) | ~307 | PL/pgSQL trigger functions + `RAISE EXCEPTION`, `RETURN NEW/OLD/NULL` |
| Reserved word identifiers | table `user` | Quote as `"user"` (portable to SQLite too); ~26 domain query sites |

## 5. Query layer

- Domain sqlair queries are mostly portable. 211 `ON CONFLICT ... DO
  UPDATE/NOTHING` with `excluded.*` work in PG (targets must match a unique
  constraint).
- SQLite-only functions in queries (portable fixes in brackets):
  - `IFNULL` x5 (`COALESCE`): `domain/access/state/user.go`,
    `domain/network/state/{unitinfo,container}.go`,
    `domain/relation/state/related_unit_watcher.go`,
    `internal/changestream/stream/stream.go`.
  - `GROUP_CONCAT` x1: `domain/application/state/unit.go` (aggregate in Go
    or dialect hook).
  - `INSERT OR IGNORE` x1: `domain/removal/state/model/secret.go`
    (`ON CONFLICT DO NOTHING`).
  - `datetime('now'[, duration])`: `domain/lease/state/state.go` (compute in
    Go and bind).
- Raw `database/sql` statements with `?` / SQLite functions:
  `internal/database/bootstrap.go`, `internal/changestream/stream/stream.go`
  (`?`, `DATETIME('now','utc')`), `core/database/schema/query.go`
  (`?`, `strftime("%s")` with a double-quoted literal), dbrepl. Estimated
  20-40 meaningful statements outside tests.
- Unknown-until-runtime risk: SQLite type affinity tolerates binding e.g. a
  Go `string` to an `INT` column or comparing int to text; PG will reject.
  Expect a tail of these, surfaced best by running domain state test suites
  against PG.

## 6. Errors, retries, isolation

- Constraint helpers (`IsErrConstraintUnique`, `...ForeignKey`, `...NotNull`,
  `...PrimaryKey`, `...Check`) are used in 40+ files; all SQLite-code based.
- `txn/transaction.go` retries only when `drivererrors.IsErrRetryable` (BUSY,
  LOCKED, "bad connection", ...): up to 250 attempts, 1 ms -> 100 ms backoff,
  25 s cap.
- PG mapping: 23505 unique, 23503 FK, 23502 not-null, 23514 check, 23P01
  exclusion; retry 40001 serialization_failure, 40P01 deadlock, connection
  class 08xxx.
- dqlite gives effectively single-writer serialisable transactions; domain
  code has read-then-write patterns without `FOR UPDATE`. PG default READ
  COMMITTED would expose races.
- `domain/sequence/state/sequence.go` upsert-increment relies on
  affected-row checks; fine under SERIALIZABLE, review otherwise.

## 7. Change stream (correctness-critical)

Flow: domain table -> trigger -> `change_log(id AUTOINCREMENT, edit_type_id,
namespace_id, changed, created_at)` -> per-namespace stream worker polls
(`internal/changestream/stream/stream.go`):

```sql
SELECT MAX(c.id), c.edit_type_id, n.namespace, changed, created_at
FROM change_log c
JOIN change_log_edit_type t ON c.edit_type_id = t.id
JOIN change_log_namespace n ON c.namespace_id = n.id
WHERE c.id > ?
GROUP BY c.namespace_id, c.changed
ORDER BY c.id;
```

-> terms -> event multiplexer -> domain watchers. Each controller keeps a
`change_log_witness(controller_id, lower_bound, upper_bound)` row; the
pruner (`domain/changestream/state`) deletes `id <= min(lower_bound)`.

- The poller and pruner assume IDs become visible in commit order (comments in
  stream.go state this). Under PG, txn A may take id 10, txn B id 11, B
  commits, the poller advances past 11, then A commits: id 10 is never
  delivered and may be pruned. Result: silently missed watcher events.
- Per namespace: N models -> N+1 pollers per controller.
- No dqlite leader/cluster APIs used by stream or lease code. Lease state is
  purely transactional (unique constraints + time arithmetic).

## 8. Test infrastructure

- `internal/database/testing/dqlitesuite.go`, `domain/schema/testing/*`,
  `internal/changestream/testing`: all state tests run on dqlite/sqlite;
  many issue raw `?` SQL.
- A PG suite can slot in at the suite level (same `TxnRunner` / schema

## 9. Namespace layout trade-offs

Relevant PostgreSQL internals:

- One backend process per connection (~5-10 MB plus private catalog
  caches), bound to one database for its lifetime. Default
  `max_connections=100`.
- Every table, index, sequence and TOAST table is a separate relation with
  its own files; B-tree indexes are per table. Per-model index cost is the
  same whether models are schemas or databases.
- System catalogs are per database; their size is the sum of objects in that
  database. A Juju model is ~700 catalog relations.
- Cached plans record `search_path`; changing it forces replanning of
  same-text statements.

| Concern | Schema per namespace (1 DB) | Database per namespace | Shared tables + model_uuid |
|---|---|---|---|
| Connections | Pool sized by concurrency; can share one pool via `SET LOCAL search_path` | Pool per DB per controller (controllers x models x idle); PgBouncer needed early | Best |
| Catalog size | Grows with models (1k models ~ 700k relations): backend cache memory, autovacuum/pgstat overhead, slow `pg_dump`, `DROP SCHEMA` scans shared_buffers | Small per DB | Smallest |
| Index performance | Same per model | Same per model | Larger shared indexes (log growth) |
| Plan caching | Replans on search_path change unless pool per namespace | Clean | Clean |
| Create/delete model | `CREATE/DROP SCHEMA` transactional and fast | `CREATE DATABASE` non-transactional, template copy, needs CREATEDB | INSERT / large DELETE, vacuum churn |
| Privileges | Works within the single DB a charm grants | Needs CREATEDB | Single DB |
| Isolation / ops | Per-schema GRANTs, `pg_dump -n` | Strongest; per-model dump/restore; easy to shard across clusters | Needs RLS; hard to extract a model |
| Code change | Small | Small | Very large |

Takeaway: schema-per-namespace for the PoC, behind a namespace ->
(cluster DSN, database, schema) placement indirection so models can later be
sharded across databases or clusters to bound catalog size.

## 10. Concurrency alternatives (post-PoC)

Goal: models independent, no global single writer, exploit PG concurrency.

With the PoC choice (SERIALIZABLE + per-namespace advisory lock) models are
already independent: the lock key is per namespace, and SSI only reports
conflicts between transactions touching overlapping relations/predicates, so
different model schemas never conflict. Only writers within one model are
serialised on change_log, matching dqlite today.

Isolation:

- SERIALIZABLE everywhere (PoC): safest port of dqlite semantics; cost is
  40001 retries under contention and SSI predicate-lock memory. The
  predicate lock table is server-wide; 08-delete-locks exhausted it (53200)
  with two readers that each read every table of a model schema
  ([Stage 11](stages/11-future-work.md) records a READ COMMITTED
  experiment).
- READ COMMITTED + explicit `SELECT ... FOR UPDATE` / constraints on
  read-then-write paths: highest throughput; requires auditing every domain
  state method.
- Mixed: SERIALIZABLE for writers; `READ ONLY DEFERRABLE` or READ COMMITTED
  for pure reads (watcher re-queries, status).

change_log ordering:

- Per-namespace `pg_advisory_xact_lock` in trigger functions (PoC): simple;
  lock held from first watched write until commit.
- Deferred constraint trigger (`DEFERRABLE INITIALLY DEFERRED`) taking the
  lock and assigning IDs at commit time: same guarantee, lock held only
  during commit.
- Visibility frontier: store `pg_current_xact_id()` per row; poller consumes
  only rows with xid < `pg_snapshot_xmin(pg_current_snapshot())`; no writer
  serialisation, more complex poller/pruner/witness.
- Logical decoding (pgoutput/wal2json) as the change source: commit-ordered,
  no triggers; needs replication privileges and a stream worker rewrite.
- LISTEN/NOTIFY: wake-up hint only (not durable, unordered); complements any
  option above to replace fixed-interval polling.
- Database-per-namespace isolates locks by construction.
