# SQLite and PostgreSQL differences

Behaviour that differs between dqlite (SQLite) and PostgreSQL and that
Juju code depends on. Each entry gives what each backend does, where Juju
hits it, and how the PoC handles it. Cite entries by id (X1, X2, ...).
Add an entry for every new difference found, including ones only
worked around. Keep the id when its handling changes.

Verified on SQLite 3.45.1 and PostgreSQL 16.15 on 2026-10-24 unless an
entry says otherwise. Schema-only differences handled by `pgschemagen`
are summarised in section 4 rather than listed one by one.

Handling states:

- **Shared fix**: one query or DDL valid on both backends.
- **Driver rewrite**: the Stage 3 driver (`internal/database/postgresql`)
  rewrites SQL that sqlair or callers produce. This is a PoC workaround;
  long term the query layer should emit dialect-correct SQL (D5:
  upstream sqlair dialect support), or callers should avoid the
  construct.
- **Generator**: `pgschemagen` translates it (Stage 4).
- **Open**: seen, not yet handled.

## 1. Query syntax

| Id | Construct | SQLite | PostgreSQL | Handling |
|---|---|---|---|---|
| X1 | Placeholders `?` and `@sqlair_N` | Native | Uses `$N` | Driver rewrite (Stage 3, D5). |
| X2 | Empty list `x IN ()` / `x NOT IN ()` | False / true, even for NULL `x` | Syntax error | Driver rewrite (Stage 3) to `x = ANY ('{}')` / `x <> ALL ('{}')`. |
| X3 | `ON CONFLICT DO UPDATE` with no conflict target | Allowed | "requires inference specification or constraint name" | Shared fix (Stage 5): name the target. |
| X4 | Unqualified column in `ON CONFLICT ... DO UPDATE` `SET` expression or `WHERE` | Means the target table | "column reference is ambiguous" (target or `excluded`) | Shared fix (Stage 5): qualify with the table name. |
| X5 | Two-argument scalar `max(a, b)` / `min(a, b)` | Scalar | Aggregate only; scalar is `GREATEST` / `LEAST`, which SQLite lacks | Shared fix (Stage 5): `CASE`. |
| X6 | Double-quoted string, `""` or `"abc"` | String literal when no column matches (legacy misfeature) | Identifier; `""` is "zero-length delimited identifier" | Shared fix: single quotes. Test SQL in 49 files fixed on Stage 6 by `test(domain): use single-quoted string literals in test sql` (includes U6). |
| X7 | `IFNULL`, `GROUP_CONCAT`, `INSERT OR IGNORE`, `IIF`, `datetime('now', ...)` | Built in | Missing | Shared fix (Stage 5, D16): `COALESCE`, aggregate in Go, `ON CONFLICT DO NOTHING`, `CASE`, bind times or `CURRENT_TIMESTAMP`. Test SQL fixed on Stage 6 by `test(domain): replace sqlite date functions in test sql` (17 files: `datetime`, `IFNULL`) and `test(domain): replace insert or ignore and replace in test sql` (`INSERT OR IGNORE` and `INSERT OR REPLACE`, which becomes `ON CONFLICT ("key") DO UPDATE`). Stage 5 first replaced `IIF` only in the schema. Production `GetModelConnectionInfo` (`domain/model/state/controller/state.go`) still used it (`TestGetModelConnectionInfoNotFound`, found in Stage 6); fixed on Stage 5 by `fix(model): replace iif in the model connection info query`. |
| X8 | `user` as an identifier | Allowed | Reserved, and silent in some positions: `FROM user` reads the `current_user` function as a one-row table, and `u.uuid` on that alias is the cast `uuid(u)` ("operator does not exist: uuid = text") | Shared fix (Stage 5): quote as `"user"`. Fourteen test files in twelve packages used it bare; fixed on Stage 6 by `test(domain): quote the user table in test sql`. |
| X9 | Parameter with no type context, such as `$1 IS NULL` | Allowed | "could not determine data type of parameter $N" | Open (Stage 6 suites): cast the parameter. |
| X24 | `x IN name` where `name` is a table or CTE, with no parentheses | Allowed, same as `x IN (SELECT * FROM name)` | Syntax error | Shared fix (Stage 5): `x IN (SELECT col FROM name)`. Eleven production sites in `domain/application/state` (`application_endpoint.go`, `k8sservice.go`), `domain/removal/state/model` (`unit.go`, `application.go`, `storage.go`), `domain/operation/state` (`task.go`, `prune.go`) and `domain/relation/state/relation.go`. Seen as `ep_names` errors in the Stage 6 suites. |
| X29 | `JOIN` / `LEFT JOIN` with no `ON` or `USING` | Allowed; a cross join | Syntax error | Schema: an override adds `ON TRUE` to `v_model`'s `LEFT JOIN controller AS ctrli` (`0007-model.diff`, Stage 4). Test: `domain/access/state/permission_test.go` `ensurePermission` uses `LEFT JOIN permission_object_type AS pot WHERE ...` (Stage 6). No production query found. |
| X30 | `instr(s, sub)` | Built in | Missing; `strpos(s, sub)` or `position(sub IN s)`, which SQLite lacks | Open. `domain/crossmodelrelation/state/model/secrets.go` (2 queries) derives the application name with `substr(unit_name, 1, instr(unit_name, '/')-1)`. Found by a production code scan in Stage 6; not in the Stage 6 suites. The legacy offer import test used it too; fixed on Stage 6 by `test(crossmodelrelation): match secret consumer units without instr` (`substr` and `length`). The production queries stay open (U11). |
| X31 | `rowid` | Implicit column on tables without `WITHOUT ROWID`; insertion order for a non-integer primary key | No such column (`ctid` is physical and not stable) | `domain/blockcommand/state` `GetBlocks` used `ORDER BY rowid`; fixed on Stage 5 by `fix(blockcommand): order blocks by type instead of rowid` (at most one block per type, so the order is deterministic). `domain/recovery/state` reads `rowid` from `foreign_key_check` (dqlite only, X21). Found by a production code scan in Stage 6. |
| X32 | Catalog queries | `sqlite_master` | `information_schema` / `pg_catalog` | `internal/worker/dbaccessor` tracker checks `sqlite_master` for `change_log` to detect an initialised model (Stage 8 plan). `internal/worker/dbrepl` queries `sqlite_master` throughout (out of scope). |
| X33 | `octet_length(x)` of a non-text value | Any type; numbers are measured in their text form | Only `text`, `bytea` and `bit`; `octet_length(bigint)` and `octet_length(timestamptz)` do not exist (42883) | Shared fix (Stage 5, `fix(operation): measure pruned operation sizes as text`): `octet_length(CAST(x AS TEXT))`, which is portable. `domain/operation/state/prune.go` estimates operation sizes with `octet_length` over every column, including `INTEGER`, `BOOLEAN`, `DATETIME` and `object_store_metadata.size`. SQLite is unchanged. On PostgreSQL the estimate counts the text form (a timestamp is 29 bytes, not 8 stored), which is close to what SQLite stores, since it keeps datetimes as text. No portable "stored bytes" function exists. `pg_column_size(x)` or page-based `pg_total_relation_size` would need backend-aware state code; UPSTREAM-FIXES follow-up. Found in Stage 6 (`domain/operation/state` prune-by-size tests). |
| X36 | Several `ON CONFLICT` clauses on one `INSERT` | Allowed (3.35+); clauses are tried in order | One clause only; a second is a syntax error | Shared fix (Stage 5, `fix(objectstore): use a single conflict clause when putting metadata`): one untargeted `ON CONFLICT DO NOTHING`. `domain/objectstore/state` `putMetadata` had `ON CONFLICT (sha_256)` and `ON CONFLICT (sha_384)`. The table's only other unique key is the `uuid` primary key, so a reused uuid now returns `ErrHashAndSizeAlreadyExists` instead of a constraint error (new test). Every charm, resource and agent binary put failed on PostgreSQL (147 `domain/removal/state/model` failures). A scan found no other multi-clause statement. |
| X37 | `==` equality operator | Same as `=` | No such operator ("operator does not exist: bigint == integer", 42883) | Generator: trigger bodies in `domain/schema/modeltriggers.go` use `1 == (SELECT COUNT(*) ...)`, and the generated PostgreSQL triggers already use `=`. Open (Stage 5) in three production queries; proposed shared fix `=`: `domain/keymanager/state` `deleteUnusedUserKeys` (`HAVING count(...) == 0`, 6 PostgreSQL failures), `domain/storageprovisioning/state/volume.go` (`LEFT JOIN machine m ON ... == ...`) and `domain/crossmodelrelation/state/model/offer.go` (`cr.scope_id == 1`). Found in Stage 6. |
| X38 | Comma join followed by `JOIN ... ON` that references a table before the comma, as in `FROM a, b JOIN c ON a.x = c.x` | Comma and `JOIN` are the same left-associative join, so an `ON` clause can use any table to its left | `JOIN` binds tighter than a comma, so this parses as `a, (b JOIN c ON ...)`, and `a` is out of scope in the `ON` clause: "invalid reference to FROM-clause entry for table "a"" (42P01) | Open (Stage 5). `domain/removal/state/model/storage.go` `GetDetachInfoForStorageAttachment` uses `FROM storage_attachment sa, fulfilment f JOIN storage_instance si ON sa.storage_instance_uuid = si.uuid ...`, where `fulfilment` is a one-row CTE (3 `domain/removal/state/model` PostgreSQL failures). Proposed shared fix: `FROM storage_attachment sa CROSS JOIN fulfilment f JOIN ...`, which both backends parse left to right. (On SQLite, `CROSS JOIN` also stops the planner reordering `sa` and `f`; with a single-row CTE and a primary key lookup on `sa`, the plan is unchanged.) Moving the CTE first, `FROM fulfilment f, storage_attachment sa JOIN ...`, also works. A scan of production and test code found no other site. Found in Stage 6. |

## 2. Types and values

| Id | Behaviour | SQLite | PostgreSQL | Handling |
|---|---|---|---|---|
| X10 | Type affinity | Stores any type in any column and compares across types without error | Assignment casts untyped literals; `text = integer` is "operator does not exist" | Shared fix per site: U5 (node ids as text), Stage 4 FK type corrections. More expected from the Stage 6 suites. |
| X11 | Invalid UTF-8 or NUL (`0x00`) in `TEXT` | Stored as given | "invalid byte sequence for encoding UTF8" (22021); NUL is rejected even though it is valid UTF-8 | Per column. `domain/schema/storage.go` `binaryTextColumns` lists the `TEXT` columns bound as bytes. Those holding raw random bytes failed on PostgreSQL, and all are fixed in one Stage 6 commit (U8): the dqlite columns become `BLOB`, which generates `bytea`. (1) `user_activation_key.activation_key` (32 bytes from `generateActivationKey`) broke `add-user` (5 `domain/access/state` failures). (2) The eight `bakery_config` key columns (32-byte keys via `keyScanner`) failed 3 `domain/macaroon/state` tests; `InitialiseBakeryConfig` runs in the bootstrap worker (`internal/worker/bootstrap/fresh.go`), so a PostgreSQL controller would have failed there. (3) `macaroon_root_key.root_key` (24 random bytes from `dbrootkeystore`) would have failed on the first login macaroon; the tests use ASCII keys. The other listed columns hold hex, base64, JSON or YAML, which are valid UTF-8. `domain/recovery/state` tests bind `{0, 128, 255}` to them (dqlite only, see X21). |
| X12 | `BOOLEAN` | Integer 0 / 1 | `boolean` | Generator (D14). `= false` / `= true` works on both. |
| X13 | `DATETIME` / `TIMESTAMP` | Text in whatever format was bound | `timestamptz`; zone-less text is read in the session `TimeZone` | Generator (D14); connections set `TimeZone=UTC` (Stage 5 findings, `WithTimeZoneUTC`). |
| X14 | Decoded `time.Time` location | UTC (go-dqlite parses in UTC; tests compare locations) | pgx returns `timestamptz` in `time.Local` | Driver (Stage 3): every connection registers a `timestamptz` codec with `ScanLocation: time.UTC`. Seen in `modelmigration` `TestSetLastLogTransferTimeMonotonic`. |
| X23 | Go value bound to a parameter of another type | Stored with affinity | pgx will not encode a Go integer for a `TEXT` parameter | Shared fix per site: bind the declared type (PLAN.md, testing notes). `schematesting.SeedControllerTable` bound the integer `controller.DefaultAPIPort` to the `TEXT` `api_port` (56 failures in `domain/model/state/controller`); fixed on Stage 6 by `test(schema): seed controller api port as text`. `relation_status_type.id` and `relation_status.relation_status_type_id` were `TEXT` while every writer bound integers; both are `INT` on Stage 6 (U12, `fix(schema): declare relation status type ids as integers`). Open test site: `domain/removal/state/model/secret_test.go` binds integer revision ids to the `TEXT` `secret_value_ref.revision_id` and `secret_deleted_value_ref.revision_id` (22 PostgreSQL failures). |
| X25 | Boolean values in `INT` columns | `TRUE` / `FALSE` are 1 / 0, and Go bools bind as integers | A boolean expression cannot be assigned to `bigint` (42804), and pgx will not encode a Go bool for `int8` or an integer for `boolean` | Per column. `constraint.allocate_public_ip` is `INT` in dqlite to avoid the go-dqlite nullable-bool bug and its table is `STRICT`, so a PostgreSQL override makes it `BOOLEAN` (Stage 4) and status reads it as `sql.Null[bool]` (Stage 5). `removal.force` is `NOT NULL` in a non-`STRICT` table, so the dqlite column is `BOOLEAN` (Stage 6, U9), with a 4.0.12 import delta. The `allocate_public_ip` export type stays `*int64` (known gap, UPSTREAM-FIXES.md). Test SQL that binds `1` to `allocate_public_ip` (`domain/provisioner/state/model`) must bind `true`. |
| X27 | Timestamp precision | go-dqlite binds `time.Time` as ISO 8601 text with nanoseconds, so values round-trip exactly | `timestamptz` holds microseconds; pgx's binary encoding truncates stored values and parameters | Open test repairs: macaroon equality/round-trip tests and 25 removal schedule tests. Use microsecond-representable fixtures without weakening boundary assertions. Different nanosecond instants can collapse to the same PG value, so truncating both operands does not prove identical cross-backend ordering. No affected production in-memory comparison was identified in the earlier scan; that is not a universal guarantee. |
| X28 | Timestamps outside the `timestamptz` range | Any `time.Time` formats as text and compares as text | pgx's binary encoding computes microseconds since 2000 without overflow checks, so `time.Unix(math.MaxInt64, 0)` silently becomes a wrong timestamp; no error is raised | Open. Test only: `domain/macaroon/state` uses it as a "no upper bound" sentinel, so `TestFindLatestKeyCreatedAfter` and `TestFindLatestKeyExpiresAfter` find no key. Use a representable bound, such as year 9999. No production sentinel found. |
| X34 | Placeholder compared with an integer literal | Parameters are untyped; a Go bool binds as 0 / 1 and `? = 0` compares integers | The placeholder takes the type of the other operand, so `$1 = 0` makes `$1` `int4`, and pgx will not encode a Go bool for `int4` ("unable to encode false into binary format for int4") | Shared fix (Stage 5, `fix(operation): compare operation query flags with booleans`): compare with `FALSE` / `TRUE` (X12). `domain/operation/state/query.go` `GetOperations` binds `queryFlags` bools in `$queryFlags.has_actions = 0` and `= 1`. Found in Stage 6 (`domain/operation/state` query tests). |

## 3. Unspecified behaviour SQLite makes look deterministic

| Id | Behaviour | SQLite | PostgreSQL | Handling |
|---|---|---|---|---|
| X15 | `UNION` row order | Sorted, as a side effect of de-duplication | Any order (hashing) | Shared fix (U7, Stage 6): `v_model_config` returned two `agent-stream` rows when `model_config` also had the key, and `ModelConfig` kept the last. Wrong on dqlite too when the config value sorts last. The view excludes `agent-stream` and `agent-version` from its `model_config` branch and uses `UNION ALL`. |
| X16 | Bare columns with `GROUP BY` | Allowed. With a single `MIN` / `MAX` aggregate, bare columns come from the row holding the min / max; otherwise from an arbitrary row | Error 42803 | Shared fix per site (D18). The change stream `selectQuery` (`internal/changestream/stream/stream.go`) relied on the `MAX` rule, so on PostgreSQL the stream worker died and watchers never went idle (5 `domain/controllernode` failures). It is a CTE of `MAX(id)` per namespace and changed value, joined back to `change_log` (Stage 5). `internal/worker/dbrepl/worker.go` has the same query (out of scope). `domain/crossmodelrelation/state/model/secrets.go` (2 queries, open, found by a Stage 6 scan) selects `sr.uuid` and tests `sruc.current_revision` in `HAVING` while grouping by `sruc.secret_id` only, so it also picks an arbitrary row on dqlite. |
| X17 | Order of rows without `ORDER BY` | Usually insertion or index order | Any order | Shared fix per site when found (D17 for constraint tags, spaces and zones). |

## 4. Schema and DDL (generator)

Handled by `pgschemagen` (Stage 4; D10, D12, D14, D15). Detail in
ANALYSIS.md section 4.

- Forward references: SQLite resolves `REFERENCES` and view sources on
  use; PostgreSQL at `CREATE`. Reordered by the generator (D10).
- A foreign key target must be a primary key, unique constraint or
  non-partial unique index when the key is created.
- `INTEGER PRIMARY KEY AUTOINCREMENT`, `STRICT`, `IIF`, `strftime`
  defaults.
- Triggers: SQLite `BEGIN ... END` bodies, `RAISE(ABORT | FAIL, ...)`
  and `WHEN` become PL/pgSQL functions with `RAISE EXCEPTION`.
  PostgreSQL does not allow subqueries in a trigger `WHEN`
  (`schematesting.FailingTriggerSQL`, Stage 6).
- PostgreSQL evaluates column defaults before `BEFORE` triggers (D13).
- Identifiers over 63 bytes are truncated by PostgreSQL; the generator
  adds a hash suffix (D14).

## 5. Transactions, errors and connections

| Id | Behaviour | SQLite / dqlite | PostgreSQL | Handling |
|---|---|---|---|---|
| X18 | Error inside a transaction | Many constraint errors undo only the statement; conflict policy can differ | A statement error aborts the transaction unless recovered through a savepoint | Shared fix per site: avoid expected conflicts in SQL. `PinLease`, `RequireMachineReboot`, `AllowCloudType` and the unit net node insert use `ON CONFLICT DO NOTHING`; `EnsureExternalUser` checks first (Stage 5). SERIALIZABLE does not universally turn a concurrent unique conflict into 40001: 23505 remains possible depending on all writer paths. See [PostgreSQL's isolation contract](https://www.postgresql.org/docs/16/transaction-iso.html#XACT-SERIALIZABLE). Verify the actual concurrent writers before relying on retry classification; do not blindly retry every constraint error. |
| X19 | Isolation | One writer at a time | SERIALIZABLE; 40001 / 40P01 at any statement or `COMMIT` | D7; retried by `drivererrors.IsErrRetryable` (Stage 3). |
| X20 | Constraint errors | SQLite extended codes | SQLSTATE 23xxx; unique and primary key share 23505 | Mapped in `drivererrors` (Stage 3). |
| X21 | Foreign keys | Off unless `PRAGMA foreign_keys`; `PRAGMA defer_foreign_keys` | Normally enforced; SQL deferral needs `DEFERRABLE` keys and `SET CONSTRAINTS` | Harness requires enforcement. PostgreSQL model import/export is deferred (D40): `domain/modelimport/state/model/import.go` uses `PRAGMA defer_foreign_keys = 1`. A future design must cover generated FK declarations (including relocated FKs) and import transaction semantics together; adding `SET CONSTRAINTS` alone is insufficient. `domain/recovery/state` replays dqlite dumps using deferral/check PRAGMAs and remains dqlite-only. Machine reprovision test checks need a separately justified backend-specific assertion (Stage 6), not blanket removal of FK coverage. |
| X22 | Connections | In-process, cheap | Server `max_connections` (100 on the PoC server); an unbounded `database/sql` pool can exhaust it | `dbaccessor` `applyDBLimits` caps dqlite pools at 3 per database. The Stage 6 harness applies the same cap to PostgreSQL; the Stage 8 `pgWorker` must too. |
| X35 | `sql.Result.LastInsertId` | Returns the connection's last inserted rowid, even when the statement inserted no row | pgx: "LastInsertId is not supported by this driver" | Shared fix (Stage 5, `fix(keymanager): return new public key ids from the insert`): `INSERT ... RETURNING id`, read through sqlair. Verified on dqlite (go-dqlite v3.0.4, SQLite 3.53.3), mattn sqlite3 v1.14.48 and pgx v5.11.0, with both `database/sql` and sqlair. `domain/keymanager/state` `ensureUserPublicKey` was the only production site. On SQLite an unknown fingerprint algorithm inserted nothing, and the stale rowid could link the model to an unrelated key (latent bug); it now returns an error (new test). |
| X26 | Error text | The message alone, such as `model table is immutable, only insertions are allowed` | pgconn adds a prefix and suffix: `ERROR: <message> (SQLSTATE P0001)` | Anchored `ErrorMatches` patterns in tests need `.*` around the message (`domain/model/state/model` immutable-model tests, Stage 6). Production code matches errors by type, not text. |
